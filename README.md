# plasma-lrc

Виджет для панели Plasma 6, который показывает текст текущей строки песни.
Работает в двух режимах и сам переключается между ними:

- **`lrc_tty`** — периодический запуск `lrc_tty --lines 1 --raw`, работает с любым
  MPRIS-плеером через lrclib.net. Это то же поведение, что было в первой версии.
- **Spicy Lyrics API** — если играет Spotify и известен id трека, виджет делает
  один HTTP-запрос и получает тайминги слов от сообщества, от Apple Music или от
  самого Spotify. Тогда строка идёт из кэша, а подчёркнутое слово — это то, что
  сейчас поётся. Если API ничего не знает про трек — возврат к `lrc_tty`.

## Возможности

- Текст текущей строки прямо на панели, обрезается по длине (или по числу символов).
- Подсветка текущего слова, когда у источника есть пословные тайминги: целиком,
  а не по кускам, из которых слово было собрано.
- Автоопределение MPRIS-плеера: виджет сам выбирает, кто играет музыку, а не кто
  просто реализует MPRIS (см. «Выбор плеера»).
- Плеер не играет — виджет не запускает процессы (положение берётся из MPRIS).
- Пока Spicy отвечает, `lrc_tty` вообще не запускается (положение считается
  локально по часам).
- Трек (исполнитель + название) в подсказке.
- Клик по виджету открывает окно: трек, строка с подсвеченным словом и автор синхронизации.
- Настройки: интервал опроса, путь к `lrc_tty`, плеер, timestamps, иконка,
  длина текста, текст «нет слов», источник (Spicy Lyrics), ключ API, компактный
  кредит, подсветка слова (подчёркивание или жирный).

Опрос по умолчанию — раз в 200 мс (`Update every` в настройках, 200…10000).
Каждый тик — это один запуск `lrc_tty`; если он не успевает завершиться (например,
лезет в сеть за новым треком), следующий тик просто пропускается. Если хочется
меньше нагрузки — поставь 500…1000 мс.

## Spicy Lyrics

Сервис [spicylyrics.org](https://spicylyrics.org) отдаёт лучший доступный синк для
трека Spotify: пословный от сообщества, иначе Apple Music, иначе сам Spotify.
Бесплатного доступа без регистрации нет, нужен свой ключ:

1. завести приложение и ключ на [developers.spicylyrics.org](https://developers.spicylyrics.org);
2. вписать ключ в настройки виджета («Source» → «API key») **или** экспортировать
   `SPICY_LYRICS_SECRET_KEY` в окружении — переменная имеет приоритет и не светится
   в конфиге Plasma;
3. оставить галку «Ask the Spicy Lyrics API» включённой (она включена по умолчанию).

Ключ пустой или галка выключена → виджет работает только через `lrc_tty`, ровно как
раньше. Ответы складываются в `~/.cache/plasma-lrc/spicy/` и живут 30 дней. Если для
трека ничего нет, это запоминается на сутки, чтобы не спрашивать заново на каждом
повторе.

Рядом с текстом показывается короткий суффикс `· Spicy Lyrics`, который при наведении
раскрывается до `· Spicy Lyrics · made by @maker`, а в окне виджета — строка со
ссылкой на автора синхронизации.

Зеркало API задаётся переменной `SPICY_LYRICS_API_ROOT` (по умолчанию
`https://api.spicylyrics.org/v1/lyrics/`) — пригодится, если официальный хост
недоступен. Это же позволяет гонять виджет против локального сервера в тестах.

## Требования

- Plasma 6 (`libPlasma`), Qt 6.5+, KDE Frameworks 6 (`CoreAddons`, `Config`, `I18n`)
- CMake 3.20+, компилятор с C++17
- `lrc_tty` в `$PATH` (см. его репозиторий)

## Сборка

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build
cmake --install build            # требует прав на /usr/lib и /usr/share
```

## Установка и обновление

```sh
cd ~/plasma_lrc
./install.sh                 # собрать, поставить, перезапустить plasmashell
./install.sh --no-restart    # не трогать plasmashell
./uninstall.sh               # снести всё: пакет, .so, настройки, с панели
```

`install.sh` сначала удаляет старый `.so` и только потом кладёт новый. Это важно:
при перезаписи библиотеки на месте остаётся тот же inode, который уже замаплен в
plasmashell, и запущенный процесс получает битые страницы кода — виджет начинает
выдавать несуществующие ошибки вроде «lrc_tty не найден». Перезапуск plasmashell в
конце скрипта поэтому обязателен.

Виджет ставится в два места, как это делают все applet-плагины Plasma:

- `/usr/lib/qt6/plugins/plasma/applets/org.kde.plasma.lrc.so`
- `/usr/share/plasma/plasmoids/org.kde.plasma.lrc/`

Чтобы установить в систему, нужен `sudo`. Пользовательская установка в
`~/.local` не сработает без дополнительных телодвижений: Plasma ищет
applet-плагины только в `QCoreApplication::libraryPaths()`, а туда `~/.local/lib`
не входит.

Arch: `makepkg -si` из приложенного `PKGBUILD`.

`kpackagetool6` без правильных флагов бесполезен:

```sh
# так не работает: "Invalid metadata for package structure """ / "Plugin is not installed"
sudo kpackagetool6 --remove org.kde.plasma.lrc
# так работает
sudo kpackagetool6 --remove org.kde.plasma.lrc --type Plasma/Applet --global
```

После установки: «Добавить виджеты» → **LRC Lyrics**.

## Проверка без панели

```sh
plasmawindowed org.kde.plasma.lrc
```

Либо без единого окна на экране:

```sh
QT_QPA_PLATFORM=offscreen plasmawindowed org.kde.plasma.lrc
```

Список плееров, которые виджет вообще может опросить:

```sh
lrc_tty --list-players
```

## Тесты

Парсер ответа API — единственное место, где молчаливый баг стоит дорого всего:
не разобрал ответ, и виджет решает, что трека нет. Поэтому тесты живут в
репозитории и проверяют то, что API отдаёт на самом деле:

```sh
cmake -S . -B build -G Ninja -DPLASMA_LRC_TESTS=ON
cmake --build build
./build/spicy-parser-test
```

## Устройство

```
lrcapplet.{h,cpp}     C++-часть: Plasma::Applet, который держит QProcess и MPRIS
spicylyrics.{h,cpp}   клиент Spicy Lyrics: HTTP, разбор ответа, кэш на диске
contents/ui/          QML: панельное представление, окно, страницы настроек
contents/config/      main.xml (kcfg, значения по умолчанию) + config.qml
tests/                проверки парсера (нужны -DPLASMA_LRC_TESTS=ON)
metadata.json         метаданные виджета
```

C++ отдаёт в QML только состояние (`Plasmoid.text`, `Plasmoid.word`,
`Plasmoid.wordStart`, `Plasmoid.attribution`, `Plasmoid.trackInfo`,
`Plasmoid.active`, …) и зеркалит настройки, чтобы QML не работал напрямую с
`KConfigPropertyMap`. Всю отрисовку делает `contents/ui/main.qml`, окно — отдельный
`contents/ui/LyricPopup.qml` (ему передаются уже готовые строки, потому что текст
извне и должен быть экранирован в одном месте).

Записи в `contents/config/main.xml` обязаны лежать внутри `<group>`: `KConfigLoader`
дописывает группу самого апплета только к сгруппированным записям, а плоские
уходят в корень `plasmawindowedrc`/`plasmashellrc` и обратно не читаются
(см. FIXME в `kconfigloader.cpp`). Поэтому C++ читает настройки из
`config().group("General")`.

Опрос: таймер дёргает `poll()`, который за `QProcess` запускает `lrc_tty`. Если
предыдущий процесс ещё жив (например, лезет в сеть за новым треком), просто
пропускаем тик. Сторожевой таймер убивает процесс, который завис дольше 20 с.
Отсутствие бинаря не приводит к спаму: интервал временно растёт до минуты.

## Выбор плеера

MPRIS реализуют не только музыкальные плееры. Telegram Desktop, например, отдаёт
голосовое сообщение из свёрнутого окна как `Playing` — и система считает его
главным медиаплеером, хотя текста у него нет.

Поэтому при выборе виджет спрашивает у каждого кандидата, что он играет, и смотрит
на метаданные, а не на имя: у трека есть длина, альбом, номер трека и обложка, а у
голосового сообщения ничего этого нет, плюс trackid вида `/org/desktop_app/…`.
Тот, кто больше похож на музыку, идёт первым; если ничего не подошло, виджет
пробует остальных по очереди, как и раньше.

Пересчёт идёт раз в 30 с, поэтому появившийся Spotify подхватывается, даже если
до него сидел кто-то другой. Плеер, который даёт текст, уступает место другому
только если тот заметно больше похож на музыку — обрыв трека посреди песни хуже,
лишний переход. Список «Never ask» в настройках исключает плееры из опроса вообще,
если угадывать не хочется.

Когда плеер, за которым мы следили, уходит с шины, виджет чистит всё, что знал о
нём, включая лирику от API. Иначе она осталась бы висеть на панели: `poll()` при
годной лирике выходит сразу и ни до кого больше не доходит.

Положение трека MPRIS не рассылает по сигналу, поэтому оно читается один раз и
дальше домотается по монотонным часам; перечитывается при смене трека, смене
состояния воспроизведения и не чаще раза в 2 с. Из ответа `Properties.Get` вариант
приходит «как есть», поэтому он разворачивается руками: `QDBusPendingReply<qint64>`
такой ответ не принимает.

Разбор ответа API отдаёт слова, а не словарь: английский режется внутри слова
(`wa` + `nna`, продолжение помечено `IsPartOfWord`), а в китайском/японском/корейском
пробелов нет вовсе. Пробел между кусками ставится по этим правилам, иначе строка
собирается как `I rea lly want`.

Форма ответа зависит от источника, и это легко пропустить: community-синки кладут
слоги в `Content[].Lead.Syllables`, а Apple Music и Spotify — прямо в
`Content[].Text` с таймингами на самой записи, без `Lead` вовсе. Если читать только
`Lead`, то 20–50 строк Apple Music выглядят как «трека нет» и виджет молча уходит
в `lrc_tty`.
