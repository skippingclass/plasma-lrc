# Changelog

## 1.9.0 — 2026-11-01

- Ограничения входных данных и защита от атак декомпрессии (Input Boundaries & Limits):
  - Централизованный контроль лимитов входящих данных (`LyricsLimits`): максимум 8 МиБ на сетевой ответ/файл, 16 МиБ на декодированный/распакованный текст, 10 000 строк, 100 000 слов/слогов, 16 384 символов UTF-16 в одной строке.
  - Потоковый сторож сетевых ответов (`attachSizeLimitGuard`) для мгновенного прерывания передачи при превышении лимита 8 МиБ без ожидания полной загрузки.
  - Потоковое ограничение распаковки zlib/gzip (`ZlibCodec::decompressWithWindowBits`) с остановкой до превышения порога 16 МиБ (защита от «decompression bomb»).
  - Строгий отказ от частичных или превышающих лимиты результатов без записи в положительный или отрицательный дисковый кэш.
  - Причины отказа `SizeLimitExceeded` прозрачно отображаются в статусах провайдеров окна диагностики.
- Фильтрация служебных строк и улучшение поисковых запросов:
  - Расширенная консервативная фильтрация служебных меток и авторов (`LyricFilter::isCreditOrNotice`): секционные маркеры (`[Intro]`, `[Verse]`, `[Chorus]`, `[Куплет]`, `[Припев]`), строки указания авторов/продюсеров с двоеточием и без (`Written by:`, `作词：`, `Producer:`, `Composer:`, `Written by Name`, `作词 某某`).
  - Сохранение временных границ в LRC: удаляемые служебные строки не растягивают время звучания предшествующей спетой строки, сохраняя невидимый разделитель `{timeMs, QString()}`.
  - Многовариантный поиск для сессий браузера (YouTube и веб-плееры): последовательная проверка исходных очищенных названий, разделения `Artist — Title` и поиска без артиста с лимитом параллельности и общим дедлайном 20 секунд.
  - Разделение параметров запроса и ожидаемой идентичности: поисковые варианты без артиста не очищают `expectedArtist`, исключая принятие лирики другого исполнителя с одинаковым названием песни.
- Ручной выбор другого совпадения («Choose another match…»):
  - Новое окно ручного выбора совпадений для поиска и переключения текстов среди 7 провайдеров (LRCLIB, lrc.red, AMLL TTML DB, NetEase Cloud Music, KuGou, QQ Music, Unison).
  - Отображение источника, названия, артиста, длительности и типа синхронизации.
  - Сортировка по пользовательскому приоритету источников с ранжированием релевантности внутри каждого.
  - Действия: «Search again», «Use selected», «Close» с состояниями поиска, загрузки, отсутствия совпадений и ошибок.
  - Защита ручного выбора: блокирует автоматическое замещение текста для текущего воспроизведения.
  - Действие контекстного меню «Use automatic selection» для быстрого возврата к стандартному автоматическому поиску.
  - Полный жизненный цикл контроллера: уникальные fetch ID, отмена предыдущих запросов и загрузок при закрытии окна или быстром переключении A -> B, 15-секундный таймаут загрузки.
  - Корректный сброс при смене трека/плеера с сохранением при режиме Repeat-One.
  - Независимость кэша: ручной выбор не перезаписывает автоматический кэш наилучшего совпадения.

## 1.8.6 — 2026-11-01

- Парсинг пунктуации и форматирование токенов (QRC/KRC/YRC):
  - Корректная расстановка пробелов после запятых, двоеточий, точек с запятой и знаков препинания.
  - Исправлена склейка и контекстный разрыв отдельно стоящих апострофов:
    - Завершающие апострофы (`fuckin' God`, `girls' night`) прикрепляются к предшествующему слову с пробелом перед следующим.
    - Сленговые начальные апострофы (`Fuck 'em`, `'cause`, `'bout`, `'til`) прикрепляются к последующему слову с пробелом перед апострофом.
    - Стяжения (`can't`, `it's`) соединяются без пробелов.
  - Контекстная обработка прямых кавычек `"`: исключены ложные пробелы после открывающих кавычек (`"Hello`) и перед закрывающими (`Hello"`), с пробелом перед следующим словом (`"Hello" world`).
- Провайдер lrc.red:
  - Исправлено ложное выставление 24-часового отрицательного кэша при обрезании очереди кандидатов (truncate > 3) при неудаче первых трёх.
  - При несинхронизированном/статическом TTML кандидата реализован fallback на LRC этого же кандидата и продолжение проверки оставшихся кандидатов в очереди.
- Провайдер AMLL:
  - Повреждённый или невалидный JSON (временный сбой сервера) больше не кэшируется как отрицательный результат на сутки.
- Пайплайн и управление чёрным списком (Blacklist):
  - Добавление трека в чёрный список немедленно отменяет текущие поисковые запросы и сбрасывает поколение, предотвращая запоздалое отображение текста.
  - Снятие трека из чёрного списка через окно настроек сразу возобновляет поиск текстов.
- Бэк-вокал и отображение:
  - Инвалидация кэша проекции бэк-вокала при смене ревизии текстов предотвращает ошибочное наложение разметки от предыдущего источника.
- Окно диагностики:
  - Точное вычисление нормализованных метаданных поиска, отображение истинного возраста замера позиции по монотонным часам и фильтрованной позиции.

## 1.8.1 — 2026-10-26

- Диагностика поиска и синхронизации (Search & Synchronization Diagnostics):
  - Новое окно диагностики, доступное через контекстное меню («Diagnostics…»).
  - Вкладка **Search**: исходные и нормализованные метаданные (название, артист, длительность), текущий провайдер, качество синхронизации, таблица статусов всех провайдеров конвейера (`disabled`, `skipped`, `pending`, `searching`, `provisional`, `selected`, `failed`), подтверждённые причины отказа (несовпадение длительности/артиста, 404, rate limit) и статус кэша (`Hit (disk)`, `Hit (memory)`, `Miss`).
  - Вкладка **Synchronization**: плеер, состояние воспроизведения, разложенная математическая формула расчёта позиции (`Base MPRIS + elapsed - gaplessLead - 90ms audioLead - userOffset = Final`), курсоры основного и бэк-вокала, флаги состояния (`paused`, `hidden`, `discarded`, `blacklisted`, `intro`, `break`).
  - Экспорт и безопасность: кнопка «Copy diagnostic report» для безопасного копирования отчёта в буфер обмена без приватных токенов, ключей и текстов песен с визуальным подтверждением («Copied!»).
  - Кнопка «Refresh» для мгновенного снимка памяти без лишних сетевых запросов.
- Временный сброс текстов (Discard / Restore lyrics):
  - Пункт контекстного меню «Discard lyrics for this track» («Restore lyrics for this track») для временного скрытия текста текущего трека без добавления в постоянный блэклист.
  - Сохранение оригинала для мгновенного восстановления без повторных сетевых запросов с проверкой актуальности блэклиста и активности источника.
- Настройка и переключение ноты на интро и паузах:
  - Опция «Show note symbol during intros and pauses» для гибкого переключения символа ноты во время пауз и инструментальных партий.
- Исправления отображения и переходов:
  - Устранено мерцание и сброс белой подсветки в серый цвет на уходящей строке во время анимации затухания перехода (`fadeTransition`) в режиме «Sung words become white».
  - Независимое обновление бэк-вокала при смене фраз внутри одной строки: бэк-вокал больше не застывает со старыми координатами при неизменном `lineIndex`.
  - Корректный пересчёт спетой части белым при перемотке назад внутри текущей строки.
  - Корректная обработка времени истечения срока кэша (`expiryGeneration`) после цепочки действий Discard → Restore.

## 1.8.0 — 2026-10-24

- Режим пословного отображения «Sung words become white»:
  - Добавлен стиль отображения (индекс 4), в котором ещё не спетые слова отображаются серым цветом, а уже спетые — белым.

  - Устранены скачки и резкое мерцание строк между старым и новым текстом.
- Корректная обработка интро и инструментальных проигрышей:

- Поддержка и раздельное отображение бэк-вокала:

  - В `SpicyLyrics` добавлен разбор массива `Background` вокала и его интеграция в общий поток строк.
  - Бэки изначально отображаются ещё более приглушённым серым цветом, плавно переходя в белый по мере пения.
- Улучшения пайплайна и сопоставления:
  - Консервативное сопоставление по названию, исполнителю и длительности с сохранением различий между версиями треков.
  - До двух одновременных запросов текстов с общим дедлайном 20 секунд, мгновенным показом предварительных построчных таймингов и последующим переходом на пословные.
  - Принудительное обновление сбрасывает кэш текущего трека для всех провайдеров.
  - Расширенное покрытие оффлайн-тестами интеграции пайплайна, кэша, сопоставления и апплета (10 тестовых наборов в CTest).

  - Корректная обработка пробелов между XML-тегами `<span>` и внутристрочных пробелов в Apple Music TTML (устранено склеивание слов вроде `Willnotletyougo`).

  - Исправлен `restoreSyncState`: устранено ошибочное добавление 1000 мс задержки при рестарте плазмашелла, если трек завершился до или во время перезапуска.
  - Сохранение флага `m_trackJustChanged` во время буферизации на позиции 0 для надёжного отсечения устаревшего playhead предыдущего трека.
  - Ограничение RTT компенсации D-Bus до 50 мс и снижение порога `kPositionSnapToleranceMs` до 500 мс.
  - В `lrc.red` добавлена строгая проверка совместимости длительности трека при поиске, предотвращающая загрузку текстов от несовпадающих версий/ремиксов.
- Обновление настроек по умолчанию:

  - Максимальная длина строки увеличена до 100 символов (`maxCharacters = 100`).
  - Задержка скрытия на паузе уменьшена до 3 секунд (`pauseHideDelay = 3`).
  - Стиль активного пословного слова изменён на жирный (`wordStyle = Bold`).

## 1.6.0 — 2026-10-24

- Обязательная атрибуция API: имя провайдера отображается на панели, во всплывающем окне и в окне полного текста; для `source=spicy_lyrics` отдельно указаны и связаны ссылками maker и uploader при наличии данных, для Spotify и Apple Music указан только провайдер. Атрибуцию API больше нельзя скрыть; устаревший режим компактной панели (`compactPanel`) удалён.
- Компоновка панели и скрытие атрибуции LRCLIB: добавлена настройка расположения атрибуции (`attributionLayout`) с выбором «Справа от текста» (`Right of lyrics`, по умолчанию) или «Под текстом» (`Below lyrics` для стандартных панелей от 30px); для нативного источника LRCLIB атрибуция на панели скрыта и отображается только в попапе и окне песни, сохраняя стандартную однострочную высоту панели.
- Исправление геометрии и подсказок панели: длинный текст переведён на `Text.StyledText` с лимитом в одну строку, отсечением (`clip`) и фиксированной базовой шириной без наложения на блок авторства; всплывающая подсказка виджета больше не повторяет строку текста (исключая неатрибутированные строки) и выводит имя активного провайдера.
- Окно полного текста песни (ридер) и разделение копирования: окно полного текста («Open song lyrics…») поддерживает все источники без караоке-разметки; для данных API доступно только стандартное экранное выделение и ручное копирование (Ctrl+C), а кнопки «Copy all lyrics», «Copy selection» и пункт контекстного меню «Copy current lyric line» зарезервированы исключительно для нативного LRCLIB (эндпоинты выгрузки или скачивания отсутствуют).
- Строгий срок хранения и очистка кэша: все ответы API хранятся на диске не более 30 дней (построчный синк — 2 дня, негативный кэш — 1 день), а ответы с неизвестным или неположительным сроком действия отклоняются; кэш принудительно очищается на диске, в оперативной памяти и в открытом окне ридера при запуске, доступе и по таймеру обслуживания во время работы виджета (фоновая очистка при остановленном приложении/ПК не выполняется).
- Блокировка кэша при приостановке приложения: получение ответа `application_suspended` блокирует выдачу кэшированных текстов API до получения свежего авторизованного ответа HTTP 200; обычные сбои сети и HTTP 429 по-прежнему позволяют использовать действующий локальный кэш; нативный источник LRCLIB продолжает работать независимо.
- Онбординг на базе клиентских ключей: виджет подготовлен для работы с индивидуальными клиентскими ключами (`sl_pk_...`) через шаблон приложения в каталоге без использования общих встроенных ключей; переменная окружения `SPICY_LYRICS_SECRET_KEY` сохранена для совместимости и принимает клиентские ключи.
